# Reconstructed Project: NORTH Loader & NRTH Hook (Result Class R2 / D2)

Behavioral reconstruction + interface definitions reverse-engineered from the supplied
`NORTH.zip` (`NORTH LOADER.exe`, `NRTH.dll`) during an authorized MTA:SA blue-team
investigation (`../mta_blue_team_case/`).

> **Scope:** intended for authorized private-server validation and defensive study only.
> Not for public-server use. No invented cheat features, and no new stealth/evasion was added.
>
> **What the original's `0x10005b80` / `0x10020640` logic is now known to be** (mapped after
> the string-decoding pass — it is no longer class U): a pattern-based resolver that installs 11
> MinHook detours in `client.dll` (plus 20 offset lookups with no hooking) and a `netc.dll`
> cluster that writes a single `0xC3` over six check functions. Full evidence:
> `../mta_blue_team_case/mechanism_overview_ar.md` §§3–4 and `working/sigs.json`.
>
> **Deliberately not implemented:** the two halves that *make it a cheat* — taking over the game's
> live Lua `exec` trampoline (global `0x1013c94c`) and writing the `0xC3` kills into another
> process. Both need cross-process memory writes and their output is a working cheat. What this
> repo builds instead is the detector for exactly those mechanisms: **`NRTH_audit.dll`** (see
> `../mta_blue_team_case/detection/audit_tool.md`), which is functional, tested and shipped.
> Menu feature slots in `nrth_ui.cpp` stay labeled stubs.

## Project Layout

- `src/north_loader.cpp` — full reimplementation of `NORTH LOADER.exe`: CLI
  (`--proc`, `--dll`, `--autoclose`, positional `.dll`), `SeDebugPrivilege`, 60 s
  process poll (Toolhelp32), classic `CreateRemoteThread(LoadLibraryA)` injection,
  `SetWindowsHookExA(WH_GETMESSAGE)` fallback on ACCESS_DENIED with on-disk PE export
  parsing (`NVXHookProc`), post-injection module verification.
- `src/nrth_hook.h` — public interface (`NVXHookProc` export contract).
- `src/nrth_hook.cpp` — full reimplementation of `NRTH.dll`: `NVXHookProc` pass-through
  export (ordinal 1), `DllMain` (disable thread calls + module PIN + init thread),
  MinHook detour on `ntdll!LdrLoadDll` watching `client.dll`/`netc.dll`, D3D9 vtable
  acquisition, `Present` (idx 17) / `Reset` (idx 16) hooks, Dear ImGui **v1.92.9**
  overlay ("North Cheat", INSERT toggle). Documented R2 deviations are listed in the
  file header.
- `src/nrth_dll.def` — export definition (`NVXHookProc @1`).
- `src/nrth_audit.h` / `src/nrth_audit.cpp` / `src/nrth_audit.def` / `src/nrth_audit_sigs.h` —
  **the defensive audit module** (`NRTH_audit.dll`, PE32 x86, 23 exports): read-only PE walker,
  the sample's positional-XOR codec (`NrthXorTransform`/`NrthXorCrack`), a pattern compiler/scanner
  with the same `?` semantics as the sample's resolver `0x10002960`, a prologue tamper classifier
  (`E9`/`FF 25`/`68..C3`/`C3`/`C2`/`C7 05`), the 20-signature High-confidence catalogue
  (`nrth_audit_sigs.h`, generated by `tools/gen_nrth_audit_sigs_h.py` from `working/sigs.json`), and
  a `.data`/`.rdata` sweep for prologue-anchored hidden records. No process access, no writes, no
  injection — see the "non-goals" block in the header.
- `tools/nrth_audit_cli.cpp` — CLI front end: `selftest`, `signatures`, `decode`, `sweep`,
  `audit --csv`, `diff <known-good> <loaded>` (A/B: reports only located functions whose state
  changed, and separates "pattern absent from the other build" from tampering).
- `run_all_tests.sh` — re-runs every test claim of this case in one command: audit unit tests (27),
  the 21 sample-derived self-test vectors, the loader CLI tests, the export-contract differential
  against the original sample, the detector's false-positive/negative controls, and the YARA
  compile+scan check. Prints `N passed, N failed, N skipped`.
- `tools/nrth_strings_recover.py` — recovers all 82 decryptors / 63 plaintexts (`working/recovered.json`).
- `tools/nrth_hook_targets.py` — per-owner-function pattern-scan and `MH_CreateHook` counts.
- `tools/nrth_patch_map.py` — the 6 one-byte `0xC3` write sites and their writer semantics.
- `tools/nrth_sig_export.py` — the 28-signature catalogue (`working/sigs.json`), anchored on prologues.
- `tools/gen_nrth_audit_sigs_h.py` — regenerates `src/nrth_audit_sigs.h` so the compiled table cannot
  drift from the evidence.
- `tools/nrth_case_strings.py` — regenerates `../mta_blue_team_case/detection/recovered_strings.txt`.
- `tools/pe_summary.py` — dependency-free PE header/section/export verifier (used by `build_audit.sh`).
- `vendor/` — pinned third-party libs the original also embedded:
  MinHook (sample: v1.3.3) and Dear ImGui v1.92.9 (sample: 1.92.9 WIP 19283).
  Fetched by `fetch_vendor.sh` (not committed).
- `tests/test_cli_parser.cpp`, `tests/test_pe_export_parser.cpp` — unit tests
  (the latter differentially validates export `NVXHookProc` @ RVA `0x0000B9E0`
  against the ORIGINAL sample `working/NRTH.dll`).
- `build.sh` — reproducible cross-build (Linux → Windows PE32 x86) via Zig's bundled
  MinGW sysroot. `build.ps1` — MSVC x86 alternative. `BUILD_LOG.txt` — last build
  and verification results.

## Build (cross, from Linux — this is the path that was executed)

```bash
# 1) toolchain (PyPI; bundles the MinGW-w64 sysroot)
pip install ziglang

# 2) pinned third-party sources
bash fetch_vendor.sh

# 3) build -> bin/NORTH_LOADER.exe + bin/NRTH.dll
bash build.sh
```

## Audit module build (`NRTH_audit.dll`) — this is the executable deliverable

```bash
bash build_audit.sh            # host unit tests + self-test, then Zig cross-build to PE32 x86
bash build_audit.sh --host     # host binaries only (bin/host/nrth_audit)
bash build_audit.sh --regen    # re-derive src/nrth_audit_sigs.h from working/sigs.json first
```

## Fidelity status

- Interfaces (export name/ordinal, CLI contract, injection call sequence, D3D9 slot
  indices, INSERT toggle): backed by disassembly evidence — see `../analysis/function_map.csv`.
- Runtime behavior on real Windows/MTA:SA: **NOT tested in this engagement** — see
  `../mta_blue_team_case/private_server_tests/results.md`. A passing build is not proof
  of behavioral equivalence.
- Audit module (`NRTH_audit.dll`): logic **is** tested (host unit tests + 21 evidence vectors +
  differential agreement with the Python tools on the real sample), but the *Windows binaries* were not
  executed here (no Windows in the sandbox). Run `nrth_audit.exe selftest` on a Windows host before
  trusting a verdict.
- Because `NRTH_audit.dll` performs no injection and no writes, it is the one artifact here that can be
  run as-is on a defender's machine; the loader/payload reconstructions are reference implementations.
